1. Overview & Capabilities

This simulator models labor-intensive sequential manufacturing lines where bundles of pieces flow through stations, each staffed by operators sharing pooled machine/tool resources.

What it can simulate:
  • Garment/sewing assembly lines (its primary domain)
  • Wire harness assembly, shoe manufacturing, leather goods
  • Manual electronics assembly, upholstery
  • Any sequential-flow, labor-intensive process
  • Multi-product lines with demand-driven or mix-driven scheduling
  • Equipment breakdowns (fixed delay or MTBF/MTTR distributions)
  • Operator learning curves (skill improvement over time)
  • Material supply constraints (starvation tracking)
  • WIP limits / kanban backpressure
  • Changeover times between products
  • Shift breaks and warmup periods
  • Multi-line shared resource pools
  • Parallel/branch routing with merge points (predecessor-based DAG)
  • Multi-path routing (different products, different operation paths)
 What it cannot simulate (yet):
  • Continuous-flow manufacturing (chemicals, food processing, steel)
  • Job-shop scheduling (dynamic routing through shared machines)
  • Highly automated cells (CNC, robotics with fixed cycle times)
  • Batch process accumulation (e.g., dyeing, heat treatment)

3. Quick Start (5 minutes)

  1. Open the simulator at /sim on your clauded web dashboard
  2. Click "Sample Data" to load the T-shirt manufacturing example
  3. Click "Validate" — should show green "PASS"
  4. Click "Run Simulation" — results appear below
  5. Look at the Line Layout — bottlenecks are red, donors are green
  6. Try clicking + on a bottleneck station — it re-runs automatically
  7. Click "Monte Carlo (30)" for confidence intervals
  8. Try "Export" to save your config as JSON for later

5. Schedule & Shifts

Configure shifts (1-3), hours per shift, work days per week, and optional overtime. Total daily hours must not exceed 24.

6. Demand Configuration

Demand-driven: Set daily and/or weekly demand per product directly.
Mix-driven: Set total daily demand + percentage mix per product (must sum to 100%).

7. Advanced Features

V2 mode: Set breakdown probability % per machine tool. When triggered, fixed 30-minute delay.

V3 mode: Configure MTBF (Mean Time Between Failures) and MTTR (Mean Time To Repair) per machine. Failures follow exponential distribution, repair times follow triangular distribution around MTTR.

Define changeover delay (in minutes) when switching from Product A to Product B on the same machine. Critical for multi-product lines.

Config: changeovers: [{from_product, to_product, changeover_minutes}]

Set maximum WIP per station. When the queue is full, upstream stations block (backpressure). Models real floor space constraints.

Config: wip_limits: [{machine_tool, max_wip}]

Model operator skill improvement over time: grade(t) = grade_final - (grade_final - grade_start) × e^(-λt)

Config: learning_curves: [{machine_tool, grade_start, grade_final, learning_rate}]

Define material supply with initial stock and replenishment schedule. Operations consume material per piece — if stock runs out, the station waits (starvation).

Config: materials: [{material_id, initial_stock, replenishment_qty, replenishment_interval_minutes}]

Config: material_requirements: [{operation_step, product, material_id, qty_per_piece}]

Breaks: 2×15min + 1×30min per 8-hour shift. Enable with enable_breaks: true

Warmup: First 30 minutes of each shift at 80% efficiency. Enable with enable_warmup: true

Operations can specify predecessors to define a DAG (Directed Acyclic Graph) instead of strict sequential flow.

Parallel branches: Two operations with the same predecessor run concurrently.

Merge points: An operation with multiple predecessors waits for ALL to complete.

Multi-path: Different products can have different operation sequences through shared machines.

Config: predecessors: ["PRODUCT:step", "PRODUCT:step"] on each operation

Example: Cut (step 1) → Sew Left (step 2, pred: 1) + Sew Right (step 3, pred: 1) → QC (step 4, pred: 2+3)

If no predecessors specified, falls back to sequential step order (V2 compatible).

Share operator pools across parallel lines (e.g., shared QC, shared cutting). The shared pool replaces individual tool resources.

Config: shared_resource_pools: [{pool_name, machine_tools: [...], total_capacity}]

9. Monte Carlo Simulation

Runs N replications (default 30) with different random seeds. Reports:

  • Mean ± StdDev for throughput, cycle time, WIP
  • Percentiles: P5 (worst case), P50 (median), P95 (best case)
  • Demand Met %: How often the line meets demand across all replications
Use Monte Carlo whenever stochastic elements are present (variability, breakdowns, rework). A single run can be misleading.

11. Sensitivity Analysis

Sweep a parameter (demand, operators, or shift hours) across a range (e.g., ±20% in 5 steps) to see how output changes. Helps answer: "How sensitive is my line to demand changes?"

13. Formulas & Algorithms

Processing Time: Actual = SAM × (1 + Variability + FPD/100 + (100-Grade)/100 + WarmupPenalty)
Variability: Triangular distribution centered at 0, range ±10%
Learning Curve: grade(t) = grade_final - (grade_final - grade_start) × e^(-λt)
Bottleneck: Station with utilization ≥ 95%
Donor: Station with utilization ≤ 70% AND operators > 1
Coverage: OK ≥ 110%, Tight ≥ 90%, Shortfall < 90%

14. Known Limitations

  • Parallel routing requires explicit predecessor configuration (not auto-detected from step numbers)
  • No batch accumulation (wait for N bundles before starting)
  • No continuous-flow modeling (flow rates, tank levels)
  • No job-shop dynamic routing
  • Bundle rework extracts single pieces; rest of bundle continues
  • Weekly capacity assumes uniform daily production
  • MiniZinc must be installed for optimization features
